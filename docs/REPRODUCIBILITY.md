# Reproducibility protocol

Use the exact source, configs, requirements-lock.txt and raw snapshot hashes recorded in the final run. Original DOCX hash and verified paragraph/TOC references are in THESIS_TRACEABILITY.md. Historical Table 4 and survey claims are independent of computed results. All superseded diagnostic runs are retained locally with explicit status and excluded from the defense bundle/default UI.

1. Run nvidia-smi and `python -m xai_finance.cli doctor`. Inspect artifacts/environment/current.json for GPU model, VRAM, driver, PyTorch runtime, CPU fallback reason and LSTM finite-operation check.
2. Set PYTHONHASHSEED=42 before starting Python; launch scripts also set CUBLAS_WORKSPACE_CONFIG before CUDA initialization. seed.py fixes Python/NumPy/torch/CUDA seeds and deterministic settings. The numerical experiment and dataset YAMLs define every reconstruction default.
3. Verify existing snapshots using the CLI validate command. It recomputes file hashes and validates chronological dates, required schema and OHLC consistency. Retrieving a fresh provider history can introduce revisions; do not overwrite the pinned snapshot and call it the same experiment.
4. Execute tests, then train, explain and report through the CLI or run_full.py. Selection uses validation only. All final metrics use original units and common test dates. A new timestamped run prevents silent overwriting. Checkpoint best/last states, scalers, ordered features, lookback, losses, validation trials, batch probes, precision and environment are saved.
5. Run verify_artifacts.py. It verifies the hash inventory, maps labels/cutoffs back to the genuine source CSV, recomputes saved metrics, checks common dates, reloads all models on CPU, and checks explanation backgrounds/additivity/paired dates. Inventory excludes its own file and its independent verification receipt to avoid self-reference.
6. Repeated RF inference sums trees serially to avoid nondeterministic parallel floating-point accumulation. Parallel training is retained. This corrects observed approximately 2.84e-14 last-bit changes, without weakening the unchanged-forecast assertion. Early diagnostic runs used parallel inference; stored forecast equivalence on CPU is verified with the recorded tolerance.
7. Offline dependency wheelhouse includes the official hash-verified torch 2.5.1+cu121 Windows wheel and wheels for every locked package. Run setup_offline.py in a fresh Windows Python 3.12 environment. No network indexes are enabled. Install the built project wheel, then execute offline_smoke.py and verify_artifacts.py. Report actual clean-env outcomes in artifacts/tests/; do not infer success merely because installation or a health endpoint succeeds.
8. Generate the defense package and ZIP only after verification. PACKAGE_MANIFEST.json hashes files; the local archive gets CRC and SHA256 checks. Transfer the ZIP to a second physical device/cloud and verify its hash before travel. The delivered local ZIP and folder share a disk; a second external copy cannot be claimed without evidence.

Replaying saved models should reproduce forecasts within declared FP32/CPU tolerances. Retraining with identical versions/settings improves repeatability but different device libraries, input snapshots, resource-driven batch fallback or hardware can change outcomes. Source code and lock hashes are captured in run.json by report generation. No fresh test metric should be used to choose another hyperparameter configuration.
